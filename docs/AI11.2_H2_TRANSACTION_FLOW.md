# AI11.2.H2 – Transaction Flow (Orphan Session Prevention)

## Problem

Creating an `AttendanceSession` before upload left orphan **Pending** sessions when photo upload failed.

## Solution

`AttendanceSessionCreator.CreateAndUploadClassroomPhotoAsync` wraps session creation and upload in a single `IUnitOfWork.ExecuteInTransactionAsync` block.

## Success flow

```
Begin transaction
  → CreateForPhotoAttendance()
  → Add session to context
  → Validate image (IClassroomImageValidator)
  → Save variants (IClassroomImageStorageService)
  → AttachClassroomImage()
  → MoveToPending()
  → SaveChanges
Commit transaction
  → Queue AI processing (after commit)
```

## Failure flow (validation)

```
Begin transaction
  → CreateForPhotoAttendance()
  → Add session to context
  → Validation fails
  → Exception thrown
Rollback transaction
  → No AttendanceSession persisted
Return error to caller
```

## Failure flow (storage)

```
Begin transaction
  → CreateForPhotoAttendance()
  → Validation succeeds
  → Storage throws
  → Delete partial storage (AttendancePhotoService cleanup)
  → Exception thrown
Rollback transaction
  → No AttendanceSession persisted
Return error to caller
```

## Existing session upload

`AttendancePhotoService.UploadClassroomPhotoAsync` (existing session ID) also uses a transaction. Upload failure rolls back image metadata changes; the pre-existing session remains.

## Rollback guarantee

| Scenario | Session in DB | Image in storage |
|----------|---------------|------------------|
| Validation failure | No | No |
| Storage failure | No | Cleaned up |
| SaveChanges failure | No | Cleaned up |
| Success | Yes (Pending + image) | Yes |
