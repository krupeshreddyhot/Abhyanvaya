# AI22.5 Phase 6 — Context Hierarchy Architecture (Design)

## Vision

Enterprise SaaS context chain:

```
Global → University → College → Campus → Department → Course → Section
```

**AI22.5 implements College scope only.** This document defines extensibility without changing current behavior.

## `ContextType` enum

| Value | Status |
|-------|--------|
| `Global` | Implemented (SuperAdmin without selection) |
| `College` | Implemented |
| `University` | Reserved |
| `Campus` | Reserved |
| `Department` | Reserved |
| `Course` | Reserved |
| `Section` | Reserved |

## Extension interface

```csharp
public interface ITenantContextHierarchy
{
    ContextType SupportedScope { get; }
    Task<TenantContextValidationResult> ValidateScopeAsync(int entityId, CancellationToken cancellationToken = default);
}
```

Future implementations register per scope (e.g. `CampusContextHierarchy`) without modifying `ITenantContextService` consumers.

## Future `TenantContextSnapshot` fields (not added yet)

- `SelectedUniversityId`
- `SelectedCampusId`
- `SelectedDepartmentId`
- `SelectedCourseId`
- `SelectedSectionId`
- `HierarchyPath[]` for breadcrumb UI

## Migration path

1. Add hierarchy validator implementations one scope at a time.
2. Extend `SetCurrentContextAsync` overloads or dedicated endpoints (`POST /api/context/campus`, etc.).
3. UI cascades selectors (University → College → Campus …).
4. `ResolveForOperation()` resolves deepest selected scope to a single effective `TenantId` or composite filter key.

## Storage

Same `ITenantContextStore` key per user; snapshot version field (`v2`) can carry expanded hierarchy when introduced.

No breaking changes to AI22.5 college-only deployments.
