# AI20.1 Architecture Validation

## Layering

```
EnrollmentHub (orchestration)
    → IEnrollmentAuthorizationService (authorization)
    → IBatchCancellationService / IBatchRetryService (commands)

EnrollmentHistoryService / BroadcastService
    → IEnrollmentSignalRPublisher (routing)
    → IHubContext<EnrollmentHub> (transport)
```

## Principles Verified

- No authorization logic inside hub beyond orchestration
- No direct repository access from hub
- No duplicated authorization between REST and SignalR (shared service)
- Publisher owns all group routing
- DI-only registration; no static authorization helpers

## Configuration / Migration

- `IEnrollmentConfigurationValidator` — boot-time production gate
- `IMigrationCompatibilityValidator` — schema drift detection

## Validated Against AI20

No enrollment pipeline business logic changed. Security and operations hardening only.
